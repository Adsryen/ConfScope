## 根因与方向为什么正好是"靠前"

编辑态两层：透明 `textarea`（画光标/选区）叠 `pre.code-editor-pre > code`（画字形）。
UA 样式表给 `code` 写着 `font-family: monospace`，轮107 只给浏览态 `.code-area code` 补了 `font: inherit`，
编辑态漏。通用 monospace 按系统解析，与应用字体栈 `"SF Mono","JetBrains Mono",Menlo,Consolas,monospace`
在多数机器上不是同一款：

| 环境 | 光标层实际字体 | 字形层实际字体 | 每字符差 | 第 60 列 |
| --- | --- | --- | --- | --- |
| Windows/WebView2 | Consolas ≈ 0.55em（6.88px@12.5px） | Chrome 等宽默认 ≈ 0.6em（7.5px） | ≈ 0.62px | ≈ 37px ≈ 5 字 |
| 本机（无夹具） | DejaVu Sans Mono 7.526 | DejaVu Sans Mono 7.526 | 0 | 0（所以历次全绿） |
| 本机 + 复现夹具 | Ubuntu Mono 7.000 | DejaVu Sans Mono 7.526 | 0.526px | 31.6px ≈ 4 字 |

**字形层更宽 ⇒ 光标恒在其左侧**，与"靠前"完全一致；浏览态没有光标层，所以只有编辑模式出问题。

## 复现配方（Linux 上造 Windows 等价条件，跑完必须删）

`~/.config/fontconfig/conf.d/99-caret-drift-repro.conf` 用 `<match target="pattern">` 把字体栈首位
`"SF Mono"` assign 成 `Ubuntu Mono`，通用 monospace 留在 DejaVu，`fc-cache -f` 生效。备份在
`/tmp/cs/99-caret-drift-repro.conf.bak`。**这是机器级夹具**，会同时影响别的用例的字体度量，
用完删除并复跑确认（本轮已删，删除后 CARET 4 条回到"本机量不出差"的留痕分支）。

## 为什么不加运行时兜底（架构决定）

想过在 `CodeEditor` 里给 `code` 写内联字体当"自愈"。否决：字体口径就从一处变成两处，
与 `.code-editor-pre, .code-editor-ta` 同块声明、`code { font: inherit }` 这条不变式直接冲突，
正是最容易再次错位的那种结构。改成把守卫做厚：静态检查"任何能匹配到那块 code 的规则都不许另写
字体/字号/字距/左内边距"（含 11 个变异夹具），真机检查两层计算字体十项描述符 + 每字符 advance 差。
