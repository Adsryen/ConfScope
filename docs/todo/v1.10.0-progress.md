# 轮134 · c：第 5 步「执行选中」写完一项就永久灰（按项记账）

## 用户原话与现场

「变更项有多个，如果我选中其中一个配置进行变更了之后，我又选择另一个配置进行变更，执行选中这个按钮就不可用了。」
复现最短路径：三项计划 → 勾 2 项执行成功 → 再勾第 3 项 → `执行选中（1）` 仍是 disabled，
且没有任何一条提示指向真正的原因（只能退回第一步重新生成计划）。

## 根因

`executionSucceeded` 是**整份计划一次性总闸**，同时写在三处：
`executeDisabled` / `skipDisabled` / `blockSucceeded` 提示。它的语义其实是「这一趟执行成功过」，
被当成「这份计划已经用完了」用。多项目分批执行是常态，总闸与事实不符。

## 修法：把事实源换成执行器逐项回调

唯一记账来源 = `onItemResult` 里 `result === "success"` 的那些 `r.item.id`（与「已应用 N 项」用的
是同一份落笔事实，不拿勾选数重算）。半截失败也一样入账——前面真写成的那几条已经改了目标，
不记就是第二趟重写。

- 新增瞬时状态 `appliedItemIds`：**不落盘**、不动 `APPLY_PLAN_SCHEMA_VERSION`、不动历史快照解析；
  只在「换来源/换连接」那次重置（`buildDraft` 依赖 `[connections, entry]`），第 3 步人工微调、
  步骤间来回都不清账。
- 执行与预演分对象：`runPlan` 落笔走 `selectedIds`（减去已应用），只读预演走
  `resolveDryRunItemIds`（勾选优先；勾选被记账清空且整版都写完了 ⇒ 回落到刚写过的那批，
  保住 R55-D3「写完还能干跑核对现状」；用户自己点全不选不回落）。
- 界面：已应用那条打 `已应用` 徽章 + 勾选框 disabled，`全选/单选/跳过失败项` 三处都不再把它放回清单；
  确认区那句勾选数在分批之间改成「已选 N ｜ 已应用 M 项，还剩 K 项可继续执行」。
- 原因拆开：删 `blockSucceeded`，新增 `blockAllApplied`（这一版没有剩下要写的项 ⇒ 去重新生成计划）；
  整版写完时不再补一句「请至少勾选一项」（那时勾选框是灭的，指错路）。
- `executionSucceeded` 整个删除（`noUnusedLocals` 逼出来的，顺带清掉一个说谎的总闸）。

## 跨层契约迁移（不是放宽断言）

`99-s-partial-write-skip.spec.ts` PS-01 两处随行为改口径：
① 跳过出口的「剩下几条」2 → 1：已写成那条被账本当场摘掉，旧口径把它还算进「要再执行一次」的清单，
   与同一时刻行上的「已应用」徽章自相矛盾；
② 第二趟不再把已写成那条发给执行器 ⇒ `.apply-already-applied` 那条瞬时提示计数改 0，
   长期说明由行级徽章承担。最硬的那条证据保留并加强：`publishCount(writtenId) === 1`。
PS-02 不受影响（那一轮没有 success 回调，账本为空，执行按钮保持亮）。
